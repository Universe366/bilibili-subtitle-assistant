在 B 站视频页的**侧边栏**里完成：抓官方字幕 → 语音转录 → AI 总结 → 与 AI 对话 → 优化与替换 → 导出。
**无 Obsidian 集成**；所有配置都在侧边栏内完成，不另开设置标签页。

## 一、安装（开发者模式加载）

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的目录）
4. 打开任意 B 站视频页，点击浏览器工具栏上的扩展图标 → 侧边栏会在右侧打开
   - 也可以直接点播放器上多出来的 **「字幕」** 按钮

> 扩展更新后，**已打开的 B 站页面必须刷新** 才会生效（内容脚本版本握手会提示）。
>
> **怎么确认自己真的跑在新版本上**：`chrome://extensions/` 看「B站字幕助手」卡片上的版本号；或打开侧边栏，最上方的**构建指纹**会显示 `版本 · 模块数 · 构建时间`。如果看到的是旧版本号，说明加载的还是旧目录，点该卡片上的**刷新图标**（⟳）重新加载。
> 这一条很重要：错误提示里的文案会随版本变化，例如 1.3.0 会在 ASR 400 时多出一行「模型列表里没有 xxx」。

### 更新（不丢设置）

手动加载的扩展不会自动更新。**覆盖原目录**更新时扩展 ID 不变，`chrome.storage.local` 里的设置会保留；如果解压到新文件夹再加载，扩展 ID 会变，旧设置就读不到。

推荐步骤：

1. 打开 **设置 → 诊断与关于 → 版本更新**，点「先备份设置」，保存导出的 JSON（含 API Key 明文，请妥善保管）。
2. 下载新 zip，**解压覆盖原来的 `bilibili-subtitle-assistant/` 目录**（`manifest.json` 所在层），不要新建文件夹。
3. 打开 `chrome://extensions/`，点扩展卡片上的**刷新**（不要移除扩展）。
4. 刷新所有已打开的 B 站页面。
5. 如果确实换了目录导致设置丢失，到 **诊断与关于 → 设置备份** 点「导入设置」，选择刚才的 JSON。

> 长期方案是上架 Chrome / Edge 商店，由浏览器自动更新并使用稳定 ID；目前 GitHub Releases 分发只能按上面的方式手动更新。

## 二、第一次使用（3 步）

| 步骤 | 位置 | 说明 |
|---|---|---|
| 1 | 设置 → AI 平台 | 默认 **DeepSeek**。点「申请 Key」拿到 Key，粘贴后点「保存设置」，再点「测试连接」 |
| 2 | 设置 → 语音识别 | 默认 **硅基流动（SiliconFlow）**。没有官方字幕时用它做语音转录 |
| 3 | 直接开用 | 打开 B 站视频 → 顶部 **① 读取当前视频** → **② 抓取官方字幕**（没有就点「语音转录」）→ **③ 生成总结** / 提问 / **④ 导出** |

顶部按钮会跟着流程走：只有一个「下一步该点的按钮」，旁边是次要操作；左侧栏在没字幕时会显示 4 步引导清单。

密钥只保存在本机（`chrome.storage.local`，不同步到其它设备）；已保存的 Key 在界面上只显示末四位掩码，**输入框留空保存表示「不改动」**。

## 三、字幕是怎么拿到的（多来源）

字幕抓取不在单一来源上赌运气，而是**五路汇总、逐个尝试**（`subtitleTrackBundle`）：

| 顺序 | 来源 | 说明 |
|---|---|---|
| ① | **网络嗅探** | 在页面**主环境**挂 `fetch` / `XMLHttpRequest` 钩子，把播放器自己请求的字幕 JSON 截下来（参考 [Bilitato](https://github.com/erikzhuang55/Bilitato) 的 inject 做法）。成功率最高，而且拿到的是**已校验过身份的正文**，不用再下载 |
| ② | **播放器实例** | `player.getSubtitle()` / `getSubtitleTracks()` |
| ③ | **wbi 签名接口** | `GET /x/player/wbi/v2?aid&cid&wts&w_rid`（参考 [Bilibili-Obsidian-Clipper](https://github.com/haixiong1997/Bilibili-Obsidian-Clipper)），由后台带 cookie 直连；wbi 密钥取自 `/x/web-interface/nav` |
| ④ | **无签名接口** | `GET /x/player/v2?bvid&cid`（兜底） |
| ⑤ | **主动触发** | 页面完全读不到时，在播放器上**点开字幕菜单并选一条语言**，逼播放器发一次请求，再回到 ① 重读 |

- 字幕地址可能是**协议相对**（`//host/path`），一律补全为页面协议
- 正文 JSON 的形状有 6 种以上（`body` / `data.body` / `result.body` / `content` / 纯数组…），统一由 `extractLines` 解析，并带「像不像字幕行」的判定，**不会把字幕轨列表误当正文**
- 接口返回 `need_login_subtitle=true` 时，会明确告诉你「该视频字幕需要登录 B 站才可见」
- 缓存标识**去掉签名查询串**，同一字幕轨不会因为签名刷新而永不命中

## 四、功能地图

**字幕（左侧栏）**
- 抓取官方字幕；中文优先，自动在**多条候选轨**里逐条尝试
- **时长校验防串分 P**：末句超出视频时长 >15% 且 >12s 判为错轨；覆盖度按 ≥10min→18% / ≥5min→22% / ≥3min→25% 分档
- 全部候选都不通过时如实提示「该视频无可用字幕」，并列出**每条候选轨各自的判定结果**与**各来源明细**（页面侧 / 接口侧 / 网络嗅探 / 播放器触发），顶部同时给出「查看明细」与「语音转录」两个按钮
- 字幕缓存（标识**去掉签名查询串**，同一字幕轨不会因签名刷新而永不命中）
- 搜索 + 命中高亮、点击行跳转到视频对应时间、复制全部 / 复制单行、单行统计（句数 / 字数 / 预计朗读 / 覆盖时长）

**语音转录（没有官方字幕时）**
- 解析音轨 → **分块下载（带进度）** → 解码 → 合并为**单声道 16 kHz** → **重叠约 4s 切片** → 逐片识别 → 合并去重
- 按平台文件大小上限**自适应分片**（超限按 0.7 系数重切，最多 3 次；片长 45~600s）
- 无时间戳结果（如 SenseVoice）也能**重叠去重**，并按标点切分、约 80 字合并成行
- **三种传输方式**（设置 → 语音识别 → 高级设置可固定某一种，默认自动）：
  1. `multipart` → `POST /audio/transcriptions`，`FormData(file + model)` —— OpenAI / Groq / 硅基流动
  2. `base64-json` → `POST /audio/transcriptions`，`{model, audio: <base64>}`
  3. `chat-audio` → `POST /chat/completions`，`messages[].content[].input_audio.data = data:audio/wav;base64,...` —— 小米 MiMo 及「以对话接口暴露 ASR 能力」的模型
  400/415/422 时会**自动按阶梯换形态重试**，所以不用先猜平台用哪一种
- 随时**终止**（终止后不再消耗额度）、单片超时、并发数可配置（设置 → 语音识别）

**音轨是怎么拿到的（这部分踩过坑，单独说明）**

音轨**在页面主环境里取**，不在扩展后台取。原因是 `Referer` / `Origin` / `User-Agent` 都属于 Fetch 规范的 **forbidden header**：在 service worker 里 `fetch(url, { headers: { referer } })` 这些值会被浏览器**静默丢弃**。B 站音轨 CDN 校验 Referer，所以后台请求必然 403 —— 而且**刷新页面也没用**，因为发起方一直是扩展源，没变过。

正确做法（现在是这么实现的）：

1. **音轨地址来源按鲜度排序**：嗅探到的页面 `playurl` 响应 > `__playinfo__` > `__INITIAL_STATE__` > 播放器 API。候选一个都没有时，会主动带 **wbi 签名**请求一次 `/x/player/wbi/playurl?fnval=16` 现取
2. **按 host 排序**：`mirrorcos` / `cosov` 节点降权（最容易 403），`mirrorakam` / `akamaized` 优先；同 host 内选带宽最低的（体积小）
3. **取字节时在页面里 fetch，只带 `Range`**，`credentials: 'omit'`、`cache: 'no-store'` —— Referer 由浏览器自动生成
4. **403 / 200+text/html 都判为失败**（防盗链可能返回 200 的 HTML 页），此时**刷新地址 + 换候选节点重试**（最多 4 轮），而不是对同一个 URL 硬重试
5. 兜底：`declarativeNetRequest` 静态规则（`rules.json`）给 `bilivideo.com` / `bilivideo.cn` / `akamaized.net` 的 **XHR 请求**补 `Referer`
   - 规则**只加 Referer，绝不动 `Origin`**。改写/删除 `Origin` 会让 Chrome 拿 B 站的 `Access-Control-Allow-Origin` 和扩展的不可变 origin 比对，反而把请求打死
   - 规则也**不匹配 `media` 资源类型**，避免影响播放器自己的音视频流（曾出现「开了插件视频加载不出来」）

**AI（右侧栏）**
- 总结：流式输出，**真正渲染 Markdown**（标题 / 粗体 / 斜体 / 行内代码 / 代码块 / 表格 / 列表 / 引用 / 高亮块 / 分隔线 / 链接），流式时显示纯文本、结束后再整体渲染
  - 默认**先联网校对字幕**（术语 / 数字 / 时间 / 事实），再用更正后的字幕生成；主按钮会如实标成「生成总结（先校对）」。不想校对就点 **⚡ 快速总结**（跳过校对，更快、更省额度）。校对开关在 设置 → 联网检索，并且**不受「对话时自动联网」开关影响**
  - 每次默认抽 **12 条**待核实项（按字幕前 / 中 / 后段抽样，可调 1~16），逐条检索并做相关性过滤
  - **总结阶段不列来源、不标编号**：核对证据会先整理成 **0~3 条简短「外部补充」**，只在确实能补充或纠正视频内容时自然融入；没有就忽略，避免总结变成检索报告
  - 总结时默认带上**视频简介**（前 2000 字）；**热门评论默认关闭**，可在 设置 → 联网检索 开启
- 对话：基于本片字幕提问，流式 + Markdown 渲染，**会话可重置**，内置建议问题，支持**拖拽/粘贴导入图片与文本**
- 生成中可中止；总结可复制 / 导出为 `.md`

**优化与替换**
- AI 优化字幕（错别字 / 同音字 / 专有名词），可**联网核对**（把检索结果作为 AI 依据）
- **一键「自动全部进行」**：不逐条确认，直接应用
- 可命名保存 / **导出 / 导入 / 切换**的替换规则组；术语表
- 转录完成后自动优化 / 自动替换（**默认关闭**）

**联网检索（两种方式，作用不同）**
- **服务商检索**：走检索 API，结果作为 AI 依据，**消耗额度**。默认 **DeepSeek 官方搜索**（复用 AI 平台里的 DeepSeek Key，不用再填一次）：结果自带重排分数、权威度、发布时间与 600~800 字摘要，质量明显好于免费网页解析；也可选 Tavily / 博查 / Serper / 智谱 / 秘塔 / 百度千帆 / Brave / Exa / Jina / SearXNG / 自定义。DeepSeek 搜索按**成功请求**计费（$0.75 / 1000 次，失败与空结果不计费）
- **直接搜索引擎**：只打开结果页（Bing / Google / 百度 / DuckDuckGo / B站），**不消耗额度**、不进上下文
- 检索结果会**去重**、按重排分 / 权威度排序；进入上下文时带站点与发布日期，并明确要求模型只引用相关来源、标注 `[来源 N]`
- **按语境检索**：不直接拿「6710 亿」「2026」这类孤立词去搜，而是取命中行与前后相邻行拼成**语境窗口**作为检索词；字幕一行只有半句时也能带上主语
- **相关性过滤**：英文/数字按实体 token、中文按二字组（靠前的词权重更高）判定，`DeepSeek-V4` / `DeepSeek V4` / `deepseek_v4` 视为同一个词；只共享「发布 / 模型」这类泛词、或中文整句对不上实体的网页会被丢弃
- 只查单个实体（如「DeepSeek」）时会结合**字幕原句**过滤：只提到名字、却没谈字幕里那件事的网页不算证据
- **证据语义判定**：每条证据会标成「支持 / 反驳 / 无关」，无关的直接移出上下文；同一次调用顺带产出 0~3 条外部补充，不额外增加请求
- 判定必须**逐字引用**证据原文（4~50 字），程序会校验引用是否真的存在；对不上就当作未判定，避免模型凭标题猜「支持」
- **多来源一致 / 冲突**：按可注册域统计，`finance.sina.com.cn` 与 `tech.sina.com.cn` 算同一来源；近似转载的文本会合并，不再被当成两个独立来源。只有多来源一致才写进总结或用于改具体数字 / 时间，单一来源只作参考
- 单条核对失败会**自动重试一次**；失败条数和原因会显示在「本次联网核对」里，语义判定失败也会明确提示
- 核对支持 2~3 路并发（可随时终止），长视频的等待时间明显缩短
- **「本次联网核对」只列出真正拿到证据的查询**，每条附字幕原句与证据摘要；没搜到证据的检索词不再占位置
- AI 生成检索词前会先看**全文抽出的候选句**（带前后语境），而不是只看开头/中间/结尾的节选；生成的查询必须能在视频里找到实体依据，并尽量还原「实体 + 时间 / 数字 / 版本」的具体说法；视频没提过的实体不会拿去搜。对话也不再默认复用上一轮的检索结果，只有明确问「这些来源 / 刚才搜到的」时才复用
- 总结校对与总结补充**共用同一批证据**，不会为了「总结里提一句来源」再重复检索一遍
- 来源面板显示**条数**并按来源统计**引用次数**

**质量与批量**
- AI 章节/分段（可点击跳转）、质量自检（漏段 / 时间异常 / 语速等）
- 批量队列：一次提交多个视频，串行处理，支持暂停 / 移除 / 进度
- 历史记录（查看 / 恢复 / 删除 / 清空）、缓存复用开关

**版本更新**
- 设置 → 诊断与关于：显示当前版本 / 最新版本 / 上次检查时间
- **自动检查**（每天一次，可关）与**手动检查**；发现新版可查看说明、一键打开下载页
- 项目通过 **GitHub Releases** 分发；Edge 商店上架暂缓。更新后需在扩展页刷新并刷新 B 站页面

**导出**
- 6 种格式：SRT / WebVTT / ASS（可指定字号）/ TXT / Markdown / JSON
- 4 种模板：纯内容 / 带时间戳 / 学习笔记 / 会议纪要
- 可配置是否在正文保留时间戳、缺少时间戳时是否估算

**设置页**
- 视觉：主题（跟随系统 / 浅色 / 深色）、**字号缩放**（0.8~1.6，全部字号按比例缩放，不会出现小到看不清的 10px 字）
- **布局默认单列堆叠**（侧边栏很窄，单列最好读）；想并排看字幕和总结可切「双列」，或选「自动（宽度 <420px 才单列）」
- **平台用下拉框选**：AI / 语音识别 / 检索都有多家内置平台（AI 还内置了 Cherry Studio 对齐的一批国内外服务商），下拉框里只显示选中这一家的配置，不用来回翻；选「➕ 添加自定义平台…」即可新增。高级项（请求方式 / 音频字段名 / 官网、Key 链接）收在「高级设置」里
- 14 个分组：通用 / AI / 语音识别 / 提示词 / 替换规则 / 术语表 / 检索 / MCP / Skills / 导出 / 批量 / 历史 / 页面内 / 诊断，显式「保存设置」
- **分组可搜索**：输入 `Key` / `导出` / `超时` / `MCP` 等，只显示匹配的分组并自动展开；清空后恢复全部分组（不删除任何设置项）
- 折叠的分组标题会显示**当前配置摘要**（平台、Key 状态、模型、导出格式、规则组数量等），不展开也能判断配没配好
- 「配置状态」里的提醒可直接点「去配置」，展开对应分组并定位到 Key 输入框
- **设置备份**：诊断与关于 → 可导出 / 导入完整设置（含 API Key 明文，导出前二次确认），用于更新换目录、换机器或误重置后的恢复

**页面内**
- 播放器内嵌「字幕」按钮（可开关、提示词可配）
- 在视频画面上显示字幕（字号 / 位置可调）
- 跟随播放：侧边栏当前句高亮 + 自动滚动，可暂停 / 恢复

## 五、目录结构

```
manifest.json                     MV3 清单
src/shared/constants.js           版本、消息协议、默认提示词、分片与校验参数
src/shared/settings.js            默认配置、密钥掩码与「留空不改动」合并、就绪度判定
src/shared/storage.js             chrome.storage.local + IndexedDB（字幕缓存/音轨/历史）
src/shared/md5.js                 纯 JS MD5（wbi 签名用，逐位对齐 RFC 1321）
```

## 六、稳定性设计要点（对应需求第十二章）

1. **布尔属性一律序列化为 `"true"`/`"false"` 字符串** —— `setBoolAttr()` / `applyAttrs()` 统一处理，绝不留空字符串
2. **完整 flex 高度链**：`html/body → #app → #main → #view → .column → .pane`，逐层 `min-height:0`；**滚动容器 `.scroll-host` 不使用 `display:flex`**
3. **浮层遮罩 `pointer-events:none`**，内部卡片单独设回 `auto`
4. 「是否已配置」由后台 `computeReadiness()` 计算并下发，界面**不用掩码值重算**
5. 分组展开状态与滚动位置存 `chrome.storage.local`，面板重建后恢复
6. 内容脚本声明版本 `1.16.0`；后台 `bsub:ping` 探测到版本不一致会**重新注入**并提示刷新
   - **多版本去重**：注入前先写 `window.__bsub_expected_version__`，页面里残留的旧版 `content.js` 读到后会**主动退休**、不再应答任何消息。否则新旧两份脚本同时注册 `onMessage`，而 `chrome.tabs.sendMessage` 只返回**第一个**响应者的结果（先注册的旧版），版本握手永远收敛不了，表现为「内容脚本不支持该方法 xxx」
   - 主环境脚本（`page-bridge.js`）**无法热替换**，扩展更新后必须刷新页面；桥遇到未知方法会返回 `stale-bridge` 并带上桥版本与支持的方法列表
7. 候选标签页按「调用方指定 → 消息来源 → 已登记 → 当前活动的 B 站视频页 → 所有打开的 B 站页」**逐个尝试降级**
8. 内容脚本**不读页面全局变量**，一律经主环境桥（`world: "MAIN"`）+ DOM 通道转发
9. 页面类型与声明一致：普通视频页 / 列表页 / 番剧播放页 / 合集播放页；协议、`www`、端口都不写死
10. SPA 导航检测 = patch `pushState`/`replaceState` + `popstate`/`hashchange` + 兜底轮询；**签名用「视频 ID + 分 P + cid」**
11. 错误分类为「Key 无效 / 额度不足 / 限流 / 模型不可用 / 缺域名权限 / 网络不通」等可操作提示
12. 字幕失败区分**下载失败**与**时长不匹配**，并带上每条候选轨的判定明细

**音轨候选的来源顺序**（任一成功即可）：① 网络嗅探到的 playurl 响应 → ② `__playinfo__` → ③ `__INITIAL_STATE__` → ④ 播放器 `getAudioTracks()` → ⑤ 页面里直连的 `<audio>/<video>` 元素 → ⑥ 主动带 wbi 签名请求 `/x/player/wbi/playurl?fnval=16`

**HTTP 状态码先分清再排查**（这几类指向完全不同的原因）：

| 状态码 | 指向 | 别混淆成 |
|---|---|---|
| `401` | 凭证 / 站点不匹配 | 参数问题 |
| `400` | 参数或模型名被拒（服务端**没走到模型**） | 服务端故障 |
| `5xx` | 服务端在转录这一步**内部出错**（鉴权与格式已通过） | 参数问题 |

## 七、抓不到字幕时怎么排查

点「抓取字幕」后如果失败，顶部会出现红色提示，点 **「查看明细 / 诊断」** 可以看到两层信息：

**① 各来源明细**

| 诊断项 | 含义 |
|---|---|
| 页面侧 N 条 / 接口侧 M 条 / 网络嗅探 K 份 | 三个来源各自拿到了多少 |
| 页面来源 | 主环境桥命中了哪些：`player.getSubtitle` / `player/v2` / `player/wbi/v2` / `__INITIAL_STATE__` / `network-sniff` |
| 页面来源报错 | 某个来源失败时的 `code` 与 `message` |
| 接口有效来源 | 后台直连命中的来源：`wbi/v2` / `player/v2` / `view` / `pgc/season` |
| `need_login_subtitle=true` | 接口明确标记「该视频字幕需要登录才可见」 |
| 播放器字幕菜单触发 | 是否成功点开菜单并捕获到字幕 |

**② 候选轨明细**：每条候选轨是「下载失败」还是「时长不匹配 / 覆盖度过低」，附行数、末句时间、覆盖秒数等具体数值。

常见原因与处理：

| 现象 | 原因 | 处理 |
|---|---|---|
| 三个来源都是 0 | 该视频**确实没有字幕**（UP 未上传、也没有 AI 字幕） | 点「语音转录」，用音轨转文字 |
| `need_login_subtitle=true` | 未登录 B 站，**AI 字幕需登录才可见** | 在浏览器里登录 B 站 → 刷新视频页 → 重试 |
| 所有来源都「网络错误」 | 打不开 `api.bilibili.com` | 确认能正常访问 B 站；或直接用「语音转录」 |
| 播放器菜单触发失败（no-trigger） | 播放器还没渲染出字幕按钮 | 让视频**播放几秒**后再点「抓取字幕」 |
| 候选轨「下载失败」 | 字幕地址是短时效签名，已过期或被拒 | 刷新页面重新抓取（缓存标识已去签名，正常情况不会误判） |
| 候选轨「时长不匹配 / 覆盖度过低」 | 抓到的是**其它分 P** 或只截到片段的字幕 | 这是刻意的防串分 P 校验。多分 P 视频上官方接口有时会返回**整段视频**的字幕轨（时长远超当前分 P），这时会自动**再点一次播放器字幕菜单**、拿到带 cid 的正确字幕；若仍失败，请先让视频播放几秒再抓，或换分 P 重抓 |

**语音转录相关的诊断**

| 现象 | 原因 | 处理 |
|---|---|---|
| 「音轨下载失败 HTTP 403」 | ① 音轨地址签名过期；② 命中 `mirrorcos` 节点；③ 扩展版本旧（1.1.0 及以前在后台请求，Referer 被丢弃必然 403） | 升到 1.2.0+。新版会自动**刷新地址 + 换节点重试 4 轮**；仍失败就刷新 B 站页面（重新签一次 URL） |
| 刷新页面仍然 403 | 旧版本在扩展后台发请求，Referer 从一开始就没发出去 —— 刷新改变不了发起方 | 升级扩展后重新加载（`chrome://extensions` → 刷新图标），再刷新 B 站页面 |
| 现象 | 原因 | 处理 |
|---|---|---|
| 「没有拿到音轨地址」 | 页面侧没解析出 DASH 音轨 | 错误详情现在会**逐项列出诊断**：每个来源分别拿到几条、有没有播放器实例、cid/bvid、网络嗅探捕获了几份 playurl 响应、以及主动刷新 playurl 的 code 与 message。**先让视频播放几秒**再点「语音转录」（播放器自己会拉 playurl，嗅探即可命中）；仍失败就刷新页面 |
| 转录返回 5xx（服务端内部错误） | 与 400/401 **本质不同**：鉴权与请求格式都已通过，服务端在转录这一步出错 | 若日志显示**第 1 片成功、第 2 片起才失败**，说明凭证与格式都是通的，问题在「多片请求」上 —— 1.23.0 已把默认分片从 300s 提到 **600s**（对齐 Bilitato），415s 这类时长只需 1 片。另有 5xx / 网络错误的**自动重试**（间隔 1.2s、3s）。日志会打印**音频电平**与**每片实际上传的文件名/大小**。仍失败：点「连通性诊断」看表格，再换模型（`TeleAI/TeleSpeechASR` 或 Groq `whisper-large-v3-turbo`） |

**切片策略**（1.23.0 起对齐参考实现 Bilitato）

| 参数 | 值 | 说明 |
|---|---|---|
| 默认分片时长 | **600s** | Bilitato `DEFAULT_ASR_CHUNK_SECONDS = 600`。**分片越少越好**：每多一片就多一次请求与一次失败机会。415s 这类常见时长在 600s 下只需 **1 片** |
| 最小分片 | 45s | Bilitato `MIN_ASR_CHUNK_SECONDS` |
| 重叠 | 4s | 用于跨片去重 |
| 体积安全系数 | **0.72** | Bilitato `ASR_CHUNK_SIZE_SAFETY_RATIO`；按上限的 72% 估算单片时长，避免踩到大小限制 |
| 默认并发 | **4** | 先单独跑第 1 片（探路），成功后其余分片按 4 路并发；可在设置里调 1~8 |
| 平台单文件上限 | 50MB | 硅基流动官方上限 |

> 旧配置里「切片时长 = 300」和「上限 = 24MB」会在升级时**自动迁移**到新默认值（仅当值恰好等于旧默认值时才迁移，手动改过的其它值不动）。

**上传音频的格式**（1.24.0 起优先走 FFmpeg 流复制重封装）

| 路径 | 用在哪 | 说明 |
|---|---|---|
| **FFmpeg 流复制重封装**（首选） | 硅基流动等偏好 M4A 的平台 | 把**原始音轨字节**直接交给 FFmpeg 做 `-c:a copy -movflags +faststart`：不解码、不重采样、不重新编码，产出**普通 MP4**（moov 在前、无 moof）。编码与 B 站原始 AAC 完全一致，且**没有实时编码开销**（415s 音频重封装只需几百毫秒）。这是与参考实现 Bilitato 完全一致的做法 |
| **MediaRecorder 重编码**（兜底） | 同上，但 FFmpeg 不可用时 | 浏览器里唯一能编 AAC 的内建能力，但它**必然产出 fragmented MP4**（`ftyp + moov + moof/mdat × N`，已实测确认），硅基流动对这类文件返回 500。代价是**实时编码**（N 秒音频约需 N 秒） |
| **WAV（16 kHz 单声道）** | 其它平台 | 无需编码，零额外耗时 |

> **为什么必须用 FFmpeg**：MediaRecorder 只能产出 fragmented MP4，而服务端要的是普通 MP4。
> 这是此前反复 500 的结构性原因。FFmpeg.wasm（单线程 core，约 30.9MB，放在 `vendor/ffmpeg/`，按需加载）
> 是绕开这个限制的唯一可行手段。


设置 → 语音识别 → 高级设置里可手动指定「上传音频格式」（自动 / WAV / M4A）。


| 现象 | 原因 | 处理 |
|---|---|---|
| 转录返回 400 `Model does not exist` | 该模型名不被**转录接口**接受（能出现在 `/models` 里 ≠ 能用于转录） | 换成确定的语音识别模型：`FunAudioLLM/SenseVoiceSmall`、`TeleAI/TeleSpeechASR` |
| 接口地址与 Key 不属于同一个站（最常见），或 Key 拼错/被截断/已删除 | 错误提示会显示当前 Key 的**长度与末四位**、**当前配置的接口地址**，并**用同一个 Key 打一次 `/models` 做对照**，点名「这个 Key 在 `xxx` 这个站上无效」 | 在设置 → 语音识别里核对「接口地址」：国内站 `cloud.siliconflow.cn` 的 Key 必须配 `https://api.siliconflow.cn/v1`，国际站 `cloud.siliconflow.com` 的 Key 必须配 `https://api.siliconflow.com/v1`（两站账号与 Key 互不通用）；也可用旁边的「一键切换」 |
| 「语音识别接口拒绝了请求（HTTP 400）」 | 参数风格不匹配。**硅基流动只接受 `file` + `model` 两个字段**，且必须是 `multipart/form-data`；多传 `response_format` / `language` 会 400 | 已内置：硅基流动标记为「最小参数（file+model）」，400 时自动按阶梯降级重试。设置里「请求方式」应保持 multipart、「音频字段名」应为 `file` |
| 提示里 `model=xxx` 但**响应体是空的** | 请求形态不对，或模型名有细微差异 | 1.4.0 起会自动按阶梯尝试**三种传输方式**（multipart → base64 JSON → 对话接口 `/chat/completions` + `input_audio`）。仍失败时会去查平台的 `/models`，区分两种情况：**模型不在列表里**（附名称最接近的候选 + 可复制的准确 ID）／**模型在列表里但语音识别接口说「Model does not exist」**（说明它不是语音识别模型，附该平台可用于转录的模型） |
| 服务端返回 `{"code":20012,"message":"Model does not exist..."}` | 该模型不能用于语音识别，或 ID 与平台里的写法不完全一致（大小写、版本后缀），或**它在另一个域名下** | 1.6.0 起会自动**换域名再试**：硅基流动有 `.cn`（国内）与 `.com`（国际）两套模型目录，如果模型只在其中一个域名下存在，会自动切过去。设置 → 语音识别 → **「选择模型」** 可直接从平台返回的列表里点选；**「核对模型」** 会同时报告两个域名下是否找到该模型 |
| 「核对模型」说模型可用，但转录仍 400 | `GET /v1/models` 返回的是**账号可见的完整目录**，里面包含对话模型、向量模型等；能用不代表能用于语音识别 | 看错误详情里列出的「实际请求过的每个 endpoint」，它会把打过的 URL 全部列出来。若两个域名、三种传输方式都被拒，请点「选择模型」换一个明确的语音识别模型 |
| 「Model does not exist」 | 同上 | 点「探测模型」或「选择模型」重新选一个属于该平台的模型 |
| SenseVoice 结果没有时间戳 | 该模型只返回纯文本（官方如此） | 属正常：会按标点切成约 80 字一行，不影响总结与导出。**需要精确时间轴请改用 `XingChenAGI/XingChenASR-Diarize-V3.0`** —— 它是实测唯一返回 `segments`（含 start/end）的模型；或在 设置 → 语音识别 手动指定上传格式 |
| 字幕时间与实际对不上 | 当前模型不返回时间戳，只能**按字数估算**分布 | 转录日志里会提示「字幕时间是按字数估算的」。换成 `XingChenAGI/XingChenASR-Diarize-V3.0` 即为真实时间戳 |
| 装了新版本却看不到新增的平台 | 早期迁移只在「平台列表为空」时才填默认值，已有配置不会补入新条目 | 1.27.2 起会自动把新增内置平台**追加**到你的配置（你填过的 Key 与自定义模型不会被改动） |
| 「生成总结」按钮灰着 | 总结需要字幕作为输入 | 但**对话不需要字幕** —— 直接在下方输入框提问即可（可联网 / 上传文件 / 调用 MCP 工具） |

> 若视频正在播放时字幕正常显示、但抓取仍失败，把「查看明细」里的**各来源明细**整段复制给我，我按实际返回补一条读取路径。

## 八、已知限制

- **语音转录的解码在侧边栏内完成**（需要 WebAudio），因此转录过程中请保持侧边栏打开；终止按钮会立刻停止后续分片请求。
- 部分 B 站音轨是分片 MP4：优先整体解码，失败时自动退化为 MediaSource + 实时采集（按倍速播放采集），耗时更长但能出结果。
- AI 优化、总结、转录都会消耗所选平台的额度；转录与总结进行中可随时终止。
- **MCP 不支持 `stdio` 传输**：浏览器扩展无法启动本地进程，只支持远程的 `http` / `sse`。同理，Skills 只支持「指令型」（正文作为提示词），**不能执行 shell / python 脚本**。
- 并非所有 AI 平台都支持函数调用；模型不返回工具调用时 MCP 静默不生效，不影响普通对话。
