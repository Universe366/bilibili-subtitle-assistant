feat(ui): 操作区排版优化（真实 Chrome 量出来的）+ 布局回归体检

用户要求：「去优化优化操作」。

先量再改。jsdom 不做布局，所以「按钮太多把工具栏撑高」测试套件看不见。
真实 Chrome + 真实 panel.css 实测：字幕就绪时 @400px 操作区高 81px、4 行，
接近侧边栏可视高度三分之一，把字幕往下挤。

1) 可见按钮 7 -> 5：把「优化字幕」「复制」收进「⋯」（字幕面板菜单里本就有）。
   保留主流程：生成总结 / 快速总结 / 去提问 / 导出 / ⋯
2) 「⚡ 快速」->「⚡ 快速总结」：菜单与 AI 面板都叫这个名字，
   只写「快速」让人不确定快速的是哪一步。
3) 「⋯」菜单按流程分组并加小标题（获取内容 / 加工字幕 / 结果与记录）。
   popoverMenu 新增 { heading } 支持：纯文本、不可点击、不参与「全部禁用」判断。
4) 视频标题胶囊截断 —— 这是真 bug 级的体验问题，踩了两个坑：
   坑1：只给 .pill 加 text-overflow 不够，胶囊会随内容变宽，
        「先换行再截断」，标题仍占两行。
        解法：胶囊内部 flex + 内层 span 负责 ellipsis，min-width:0。
   坑2：标题胶囊占满一行（长标题 340px），把「240 行」挤到下一行，
        操作区还是多一行。解法：max-width:70%（不是 100% ——
        100% 会独占一行、必然多一行）。

实测效果：@360/@420 普通标题 4 行 81px -> 3 行 70px；
@360 超长标题 4 行 93px -> 3 行 70px（与普通标题一致）。

新增 verify/layout-check.mjs：真实 Chrome + 真实 panel.css 的布局回归。
因为 jsdom 不做布局，panel-test/flow2 都发现不了排版问题。
这条检查在我改的过程中真的红了两次（300px 下 4 行、超长标题 93px），
不是靠肉眼看出来的。

flow2 断言收紧（没有放松）：原来那条「常用按钮直接可见」之所以在
按钮挪进菜单后仍通过，是因为 textContent 把菜单项也算进去了 —— 假通过。
现改为明确区分「直接可见的主流程按钮」与「菜单里仍可达」，
并把可见按钮上限从 7 收紧到 6，另加「菜单带分组小标题」。

测试：23 个套件（含静态体检 + 布局体检），共 1247 项断言全部通过。
